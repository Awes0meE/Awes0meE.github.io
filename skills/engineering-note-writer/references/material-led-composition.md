# Material-Led Composition

Use this before arranging a multi-section note or repairing a rigid draft.

## Structure Follows Changing Understanding

A learning note is a reader following how an engineering situation became clearer. The structure may be chronological, conceptual, comparative, or built around one stubborn failure. Do not name or select an article type before reading the material.

Find the narrative force:

- expectation colliding with behavior;
- a symptom revealing a deeper layer;
- one constraint forcing a design decision;
- separate files beginning to explain one another;
- a small experiment making an abstract concept visible;
- a toolchain step that changed the meaning of “working.”

These are signals, not templates. Use only what the material contains.

## Build A Beat Map, Not A Table Of Contents

Before prose, sketch a few information moves. Most substantial notes need roughly four to eight, but the number is not a requirement.

Each move should add at least one of:

- a new observable fact;
- a better question;
- a changed interpretation;
- a supported reaction;
- a decision and its constraint;
- a piece of evidence that changes what can be claimed.

If two adjacent moves do the same job, merge them. If a paragraph exists only because the old template expects an opening, file list, retrospective, or future work, remove it.

## Enter Through Something Concrete

Begin close to the material: a command that chose the wrong Qt, a counter that jumped, a `final2` file beside another `final`, a bare PCB, a waveform, or a question the course brief made physical.

Avoid meta-document openings such as “这是一篇重新整理后的学习记录.” Also avoid manufactured drama. The first concrete fact only needs to make the next sentence worth reading.

## Let Knowledge Arrive Beside The Problem

Explain `74HC165`, EXTI, `windeployqt`, or a fabrication file when it changes the reader's understanding of the active situation. Do not stop the note for a detached textbook lecture.

A detour is useful when it gives the reader a tool for the next move. Return with a short connection to the board, error, file, or decision that opened the detour.

## Derive Headings After Drafting

Finish the rough body first. Then place a heading where the note genuinely changes subject.

Good headings name what follows:

- `74HC165 把十四路输入塞进了几根线`
- `DLL 都在，程序还是打不开`
- `final2 到底 final 在哪里`
- `触点抖动先替 NVIC 背了锅`

Framework headings hide the material by naming the writer's process, a generic phase, or a compulsory retrospective instead of the subject. Apply the heading limit and banned framework labels defined in `SKILL.md`. Short notes may need one heading or none. On bilingual pages, make both sides describe the same subject rather than translating a generic label.

Treat the page title as a heading too. If a draft is provisional, mark that status separately or pair it with a content-bearing title; `暂定稿 / Provisional Draft` is not enough on its own.

## Use Lists Only For Real Parallelism

Use bullets for a genuine set of files, measurements, checks, or alternatives. Do not convert a narrative into bullets because the evidence is messy. Explain why each listed item matters.

## End At The Last Useful Beat

Possible endings include:

- the final verification that settled the active question;
- the exact unknown that still blocks a stronger claim;
- a callback to the error, file, or assumption that opened the note;
- a concrete change in how the writer now reads similar systems.

None is mandatory. Stop when another paragraph would repeat the lesson or announce that the article is ending.
