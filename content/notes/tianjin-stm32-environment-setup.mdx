## “Build Succeeded” Covers Only the First Link / “Build Succeeded” 只覆盖第一段链路

A Keil project can compile while the target remains untouched. Bring-up therefore has at least four links to distinguish: project and startup configuration, STM32F103C8T6 clock and GPIO setup, ST-Link target/download settings, and a board-level observable that can confirm the program reached the MCU.

Keil 工程可以顺利编译，目标板却完全没有变化。bring-up 至少要拆成四段来看：工程与启动配置、STM32F103C8T6 时钟和 GPIO 初始化、ST-Link 目标与下载设置，以及一个能确认程序确实到达 MCU 的板级现象。

This separation matters because each link fails differently. A compiler error points back into the project; a download failure belongs to the programmer/target connection; a flashed program with no expected output sends the check toward clocks, pins, power, or control flow. The workflow becomes useful when those possibilities stop being one vague “the board does not work.”

这样拆开之后，每一段失败的样子也不同：编译错误回到工程，下载失败检查下载器与目标连接，程序已经写入却没有预期输出时，再转向时钟、引脚、供电或控制流。“板子不工作”这句话，终于能被拆成几个可检查的问题。

## GPIOB Powers the Display Before It Displays Anything / OLED 显示之前，GPIOB 先把供电电平放好

The public excerpt enables the GPIOB clock and configures pins 4 and 5 as 50 MHz push-pull outputs. It sets PB5 high and PB4 low before calling `OLED_Init()`, then writes two status strings. That order records an easy-to-miss dependency: a display API cannot compensate for missing module power levels.

公开摘录先使能 GPIOB 时钟，把 4、5 号引脚配置为 50 MHz 推挽输出；PB5 拉高、PB4 拉低之后，才调用 `OLED_Init()` 并写入两行状态文字。这个顺序记住了一个很容易被函数名遮住的依赖：模块供电电平没有就位时，显示 API 再完整也补不上。

`GPIO_Init()` looks compact, while the structure passed into it still carries mode, pin mask, and speed. The library call shortens the syntax; it does not remove the hardware choices.

`GPIO_Init()` 看起来很短，传入的结构体却仍然装着模式、引脚掩码和速度。库函数压缩了写法，没有替硬件选择消失。

## GPIOC13 Is the End-to-End Check / GPIOC13 是端到端检查

After enabling GPIOC, the excerpt configures pin 13 as another push-pull output. The loop sets the pin, waits 300 ms, resets it, and waits another 300 ms. Unlike a successful build message, that intended pattern crosses the entire chain from source and toolchain to a physical output pin.

使能 GPIOC 后，摘录把 13 号引脚配置成推挽输出。主循环依次置位、等待 300 ms、复位、再等待 300 ms。和“编译成功”相比，这个预期节奏跨过了源码、工具链、下载与物理输出引脚，适合作为端到端检查。

公开材料保留的是代码与检查顺序，不是下载日志或示波器波形。它最耐用的部分正是 bring-up 次序：先建立工程，再到达目标，最后选择一个足够小的输出，把这两件事区分开。
