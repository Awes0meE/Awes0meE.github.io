## Six Initializers Put the Interfaces on One Page / 六个初始化把接口摆上了同一页

`CLED_Init()`, `OLED_Init()`, `LightSensor_Init()`, `TIM3_Config()`, `TIM4_PWM_Config()`, and `Encoder_EXTI_Config()` appear together before the loop begins. That one group is the clearest change from the earlier single-peripheral exercises: display, sensing, timing, PWM, and edge input now have to share one program state.

`CLED_Init()`、`OLED_Init()`、`LightSensor_Init()`、`TIM3_Config()`、`TIM4_PWM_Config()` 与 `Encoder_EXTI_Config()` 在进入循环前依次出现。和前面的单外设练习相比，变化就在这一组函数里：显示、传感、计时、PWM 和边沿输入现在要共享同一个程序状态。

The OLED labels reveal what that state contains: current brightness, target brightness, LED brightness, temperature, and humidity. The screen is not decoration here; it gives each data path somewhere visible to land.

OLED 上的四行标签也把状态拆得很清楚：当前亮度、目标亮度、LED 亮度，以及温湿度。显示屏在这里不是装饰，它给每条数据路径都留了一个可见的落点。

## The Loop Has a Fast Path and a Flag-Gated Path / 主循环里有快路径，也有 flag 控制的路径

Every pass updates `set_light_value` from the encoder value and writes the target to the OLED. Light and DHT11 reads happen only when `dht_read_flag` is set; when `DHT11_Read()` enters its true branch, temperature and humidity are stored, and a second flag controls when those two numbers are refreshed on screen.

每次循环都会根据编码器值更新 `set_light_value`，并把目标值写到 OLED。光照与 DHT11 读取只在 `dht_read_flag` 置位时发生；`DHT11_Read()` 进入 true 分支后保存温度和湿度，再由第二个 flag 决定何时刷新这两个显示值。

This is still a small polling loop, but the flags keep the slower sensor branch from looking identical to the target and display updates. `TIM3_Config()` and the consumption of `dht_read_flag` are both visible; the flag's source and update period are not present in the public excerpt.

它仍然是一个小型轮询循环，不过 flag 已经把较慢的传感器分支和目标值、显示更新区分开来。公开摘录同时呈现了 `TIM3_Config()` 与 `dht_read_flag` 的消费位置，但没有给出这个 flag 的来源和更新周期。

## A Lookup Table Connects the Target to TIM4 PWM / 查表结果接到了 TIM4 PWM

The main loop makes the call relationship visible: `set_light_value` enters `Lookup_PWM_For_Target()`, the returned `ideal_pwm` is displayed, and `Set_LED_Brightness()` receives the same value for LED output.

主循环把函数调用关系摆在了一起：`set_light_value` 进入 `Lookup_PWM_For_Target()`，返回的 `ideal_pwm` 被显示出来，同一个值再交给 `Set_LED_Brightness()` 作为 LED 输出。

The mapping makes sensing, a setpoint, an observable display, and an output meet in one loop. It does not calculate an error between measured light and target light, so the excerpt supports a lookup-based brightness demo rather than a demonstrated closed-loop controller.

这条映射让传感值、设定值、可观察显示和输出在一个循环里相遇。不过代码没有计算实测光照与目标光照之间的误差，因此它支持的是查表式亮度 demo，不是已经证明的闭环控制器。

## One Loop Carries Several Update Rhythms / 一个循环开始承载几种更新节奏

The target calculation runs on every pass, light and DHT11 reads wait behind a flag, OLED refresh uses current or stored values, and the LED output is recomputed from the lookup call. Add another slow sensor, and the useful question is no longer which initializer to call; it is who owns each update and how long that work may hold the loop.

目标值计算在每轮循环里发生，光照与 DHT11 读取等在 flag 后面，OLED 刷新使用当前值或已保存的值，LED 输出则根据查表调用重新计算。如果再接入一个较慢的传感器，值得追问的就不再是调用哪个初始化函数，而是谁负责每次更新、这段工作会占住循环多久。
