## PWM Changes Pulse Timing, Not an Analogue Voltage Variable / PWM 改的是脉冲时间，不是模拟电压变量

`Set_LED_Brightness()` does not ask the MCU to output a continuous analogue voltage. It clamps `brightness` to 999, passes the value to `TIM_SetCompare1(TIM4, brightness)`, and updates TIM4 channel 1's compare register. The counter repeatedly runs between zero and its auto-reload value; the compare point determines when the output changes within each period. A complete duty-cycle interpretation also depends on `ARR`, PWM mode, and output polarity. Because the excerpt preserves only the compare update, I do not infer the missing timer setup from the number `999`.

For an LED, the load's electrical and visual response turns rapid switching into an apparent brightness change. A servo interprets similar-looking pulses as position or continuous-rotation commands. Sharing the name PWM does not mean that the loads understand the signal in the same way.

`Set_LED_Brightness()` 没有让 MCU 直接输出某个连续模拟电压。它把 `brightness` 限制到 999，再交给 `TIM_SetCompare1(TIM4, brightness)`，更新 TIM4 通道 1 的捕获比较寄存器。计数器在 0 与自动重装值之间重复运行，比较值决定一个周期内输出何时翻转；占空比还要结合 `ARR`、PWM 模式与输出极性解释。公开摘录只留下比较值更新，因此我不会从 `999` 倒推出未公开的完整定时器配置。

对 LED 来说，负载的视觉与电气响应会把快速开关表现成亮度变化；对舵机来说，同样叫 PWM 的脉冲却被解读为位置或连续舵机的运动指令。外设名称相同，不代表负载理解信号的方式相同。

The servo reference fixes a 20 ms period and maps high times from 0.5 ms to 2.5 ms onto 0° through 180°. I used it to translate a servo pulse specification into timer parameters. It is a setup reference rather than an oscilloscope measurement, and it cannot replace the datasheet for a particular servo.

舵机参考图固定 20 ms 周期，把高电平时间从 0.5 ms 增到 2.5 ms，对应 0° 到 180°。我把它作为定时器参数与舵机脉宽之间的换算参考；它不是示波器实测记录，也不能替代具体舵机的数据手册。

## The Sixteen Points Came from the Breadboard, Not a Formula / 16 个点来自面包板，不来自公式

I increased the PWM setting and read the ADC point by point using the same Blue Pill, LED, light sensor, breadboard, and ambient conditions. The resulting 16 `(pwm, adc)` pairs run from PWM 0 / ADC 1600 to PWM 1000 / ADC 480. The direction follows the light-dependent divider and sampling arrangement. This table captures the response of that physical setup; it was not copied from a theoretical sensor curve.

`Lookup_PWM_For_Target()` first handles values beyond the two endpoints, then finds the interval surrounding the target ADC code. It computes `fraction = (target_adc - adc1) / (adc2 - adc1)`, linearly interpolates from `pwm1` to `pwm2`, and rounds the result. That is smoother than switching among 16 discrete levels and avoids claiming that one global line describes the sensor over its entire range.

我把 PWM 从 0 往上调，在当时那套 Blue Pill、LED、光敏传感器、面包板和环境光条件下逐点读取 ADC，得到 16 组 `(pwm, adc)`。PWM 从 0 增到 1000，ADC 从 1600 降到 480。方向相反来自光敏分压与采样接法；表格记录的是这套实物链路的响应，不是从器件参数里抄出的一条理论曲线。

`Lookup_PWM_For_Target()` 先处理表格两端，再找到目标 ADC 所在的相邻区间。区间比例按 `fraction = (target_adc - adc1) / (adc2 - adc1)` 计算，随后在 `pwm1` 与 `pwm2` 之间线性插值并四舍五入。这样做比 16 档硬切换平滑，也不需要假设整段传感器响应可以由一个全局线性公式描述。

The calibration has deliberate limits. The ADC values remain sample codes rather than lux. I did not perform repeated measurements, error bars, or temperature-drift testing. Interpolation assumes only that adjacent measured points can be approximated locally by a straight line. That was sufficient for a low-frequency demo, not for metrology.

这次标定仍有明确边界。ADC 只是量化后的采样码，没有换算成 lux；16 个点没有重复测量、误差条或温漂测试；插值只假设相邻两点之间可以近似成直线。它足以驱动一个低频 demo，却不是传感器计量标定。

## UART Let Me See What the MCU Was Doing / UART 让我看见 MCU 里面正在发生什么

UART addressed observability. Once its baud rate, data bits, and stop bits were configured, the MCU serialized bytes to a computer. In the final demo I used it for light readings and debug prints, not incoming control commands. It neither sampled the light-sensor voltage nor changed LED duty cycle; it let internal values leave the board so I could see where the program had reached.

UART 解决的是可观察性。配置波特率、数据位、停止位等参数后，单片机把字节按串行帧送到电脑；我在最终 demo 里发送光照数据和调试打印，没有把电脑端字符做成控制指令。它既不采样光敏电压，也不改变 LED 占空比，只是让 MCU 内部的数字离开板子，便于核对程序走到了哪里。

No standalone UART source remains, and the condensed main loop omits that branch. I remember the complete demo sending its light data and debug output to the computer; the display path that can still be followed line by line is `OLED_ShowNum()`. Keeping those statements separate avoids using an absent implementation to embellish the code that remains.

当前归档没有留下独立 UART 源码，主循环摘录也裁掉了串口分支。完整 demo 当时确实向电脑发送过光照数据和调试打印；今天还能沿代码逐行读下去的显示出口则是 `OLED_ShowNum()`。我把这两件事分开写，不用一段已经缺失的实现去装饰仍然存在的代码。

## The Three Paths Met Without Closing the Loop / 三条数据路径相遇，但没有形成闭环

In the integrated demo, the encoder provided a target in the ADC-value domain; the calibration table mapped it to a TIM4 compare value; and PWM drove the LED. Light-sensor sampling, the OLED, and UART exposed the current light, target, and output. ADC, PWM, and UART therefore met in one program as measurement, actuation, and communication.

综合 demo 里，编码器给出目标 ADC 域数值，标定表把目标映射成 TIM4 比较值，PWM 驱动 LED；光敏传感器的 ADC 采样、OLED 与 UART 则让我看到当前光照、目标和输出。于是 ADC、PWM、UART 第一次在一个程序里相遇。一个读物理世界，一个驱动物理世界，一个把内部状态送出去。

The measured ADC value did not return to the mapping function to form an error. The implemented path was `target → lookup → PWM`, not `target − measurement → controller → PWM`. I considered using the light feedback for further correction, but the final result remained feedforward calibration with measurement display. Once stated that way, the exercise shows exactly where the missing return path of a closed loop would have to go.

不过实测 ADC 没有回到映射函数里参与误差计算。代码路径是 `目标 → 查表 → PWM`，不是 `目标 − 实测 → 控制器 → PWM`。我当时考虑过继续根据光敏反馈修正亮度，但最终留下的是前馈标定与实测显示。把这点说清以后，这段练习反而更有价值。它展示了闭环还缺的那条返回路径究竟在哪里。
