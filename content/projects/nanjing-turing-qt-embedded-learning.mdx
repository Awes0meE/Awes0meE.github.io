## A Matched qmake Kit Brought the Upstream App Up / 配对后的 qmake Kit 跑起了上游应用

The run-up matched the checked-out Seamly2D branch to Qt 6.5.3 MSVC2019 64-bit and the v142 toolchain. Once qmake, the full build, the deployment path, and the runtime agreed, the upstream application ran on the Windows 11 development machine. The mismatch trail and recovery steps remain in the [Qt6 first-run note](/notes/turing-qt-seamly2d-first-run).

这次 run-up 把检出的 Seamly2D 分支与 Qt 6.5.3 MSVC2019 64-bit、v142 工具链配到一起。等 qmake、完整构建、部署路径与运行时彼此一致，上游应用才在 Windows 11 开发机上运行；错配与恢复过程保留在 [Qt6 首跑笔记](/notes/turing-qt-seamly2d-first-run) 中。

Seamly2D is the upstream open-source pattern-design application used for this learning work. Its wordmark identifies the software being studied; it is not a personal visual design.

Seamly2D 是这次学习所基于的上游开源服装纸样软件。下面的标识用来说明软件来源，不是个人视觉设计作品。

## qmake Built Seamly2D; CMake and Ninja Explained the Layers / qmake 构建 Seamly2D，CMake 与 Ninja 拆解层次

The recorded Seamly2D route remained qmake. The CMake/Ninja material was a parallel study of the layers beneath Qt builds: compiler and linker, CMake configure and generate stages, the native build tool, Qt package discovery, and runtime deployment. It does not claim that this upstream project was migrated to CMake.

记录中的 Seamly2D 路线始终使用 qmake；CMake/Ninja 材料是并行展开的构建分层学习，把编译器与链接器、CMake 的 Configure 与 Generate、本机构建工具、Qt 包发现和运行时部署拆开来看，并不表示这个上游项目已经迁移到 CMake。

That distinction also determines how the public artifacts should be read. The first-run note records the qmake/Qt route; the [CMake and build-logic note](/notes/turing-cmake-build-logic) holds the parallel tutorial sources and translations. Its diagrams include an upstream tutorial image and the same image embedded in a Notion export, alongside DeepSeek-generated explanations. The archive toolchain sketch below has no author identified in the source record.

这一区分也决定了公开材料该怎样阅读：首跑笔记记录 qmake/Qt 路线，[CMake 与编译逻辑笔记](/notes/turing-cmake-build-logic)则保留并行学习所用的教程来源与翻译。相关图示包括一张上游教程图、它在 Notion 导出中的同图副本，以及由 DeepSeek 生成的解释图；下方档案草图的原始记录没有注明作者。

## Windows Closed Locally, While macOS Signing Stayed Open / Windows 本机闭环，macOS 签名仍未收口

The Windows record reaches a specific local result: a Release build, Qt dependency collection with `windeployqt`, a manual copy of `xerces-c_3_2.dll`, self-signing, an Inno Setup installer, installation, and a successful launch on the same machine. The accompanying workflow also states the missing check plainly: the installer was not tested on a clean Windows device without Visual Studio or Qt. Local installation therefore closed the learning loop, but did not establish a generally distributable or production release.

Windows 记录走到了一个明确的本机结果：Release 构建、用 `windeployqt` 收集 Qt 依赖、手动补 `xerces-c_3_2.dll`、自签名、Inno Setup 安装包、安装并在同一台机器启动成功。配套流程也把缺口写得很直白：没有在一台不装 Visual Studio 和 Qt 的干净 Windows 设备上验证。因此，本机安装闭合了学习流程，却还不能推出“已经可普遍分发”或“生产发布完成”。

On macOS, the records support Debug and Release builds, `macdeployqt`, and an unsigned DMG path. A self-signed certificate was created, while the weekly log says the automation worked except for signing. The second shell script contains `codesign`, `spctl`, and DMG steps, but a script that describes the intended sequence is not a completed signing result. Apple signing and notarization remained unfinished.

macOS 侧有记录支持 Debug、Release、`macdeployqt` 与无签名 DMG 路线；自签名证书创建成功，但周日志明确写着自动化“除签注外功能均实现”。另一份 shell 脚本虽然列出了 `codesign`、`spctl` 和 DMG 步骤，它记录的仍是目标顺序，不等于签名已经跑通。Apple 签名与 notarization 都停在未完成状态。

The [Release packaging note](/notes/turing-release-packaging-cross-platform) keeps the Windows commands and local verification. The two macOS artifacts separate the [working unsigned DMG path](/uploads/projects/nanjing-turing/macos-build-package.sh) from the [unfinished signing sequence](/uploads/projects/nanjing-turing/macos-build-package-sign.sh). The [three-week log](/notes/turing-three-week-development-log) owns the chronological change in what “working” meant, while the [XML sample note](/notes/turing-sm2d-xml-data-format) keeps the separate `.sm2d` and `.smis` reading trail.

[Release 打包笔记](/notes/turing-release-packaging-cross-platform)保留 Windows 命令与本机验证；两份 macOS 材料分别对应[已跑通的无签名 DMG 路线](/uploads/projects/nanjing-turing/macos-build-package.sh)与[尚未完成的签名顺序](/uploads/projects/nanjing-turing/macos-build-package-sign.sh)。[三周开发记录](/notes/turing-three-week-development-log)负责“能跑”含义变化的时间线，[XML 样例笔记](/notes/turing-sm2d-xml-data-format)则单独保留 `.sm2d` 与 `.smis` 的阅读线索。
