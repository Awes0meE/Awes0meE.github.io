## GPIOC13 Made the Toolchain Testable / GPIOC13 让工具链有了可验证结果

The smallest public excerpt starts by enabling GPIOB and GPIOC clocks. GPIOB pins 4 and 5 establish the OLED power levels; GPIOC pin 13 then alternates every 300 ms. That short loop gives the Keil/ST-Link bring-up route a concrete destination: the project must build, reach the STM32F103C8T6, and produce an expected pin state before another peripheral is added.

最小的公开摘录先使能 GPIOB、GPIOC 时钟：GPIOB 的 4、5 号引脚给 OLED 建立供电电平，GPIOC13 再以 300 ms 为间隔翻转。于是 Keil/ST-Link 的 bring-up 不再停在“工程没报错”，而是有了一条具体终点：程序要能构建、到达 STM32F103C8T6，并让引脚呈现预期状态，之后才适合继续叠外设。

[基础 GPIO 与 OLED 循环](/uploads/projects/tianjin-metro/stm32-basic-gpio-oled-loop.c)把这条最初链路留在了引脚图旁边。

## Edges and Timers Changed What the Board Could Notice / 边沿与定时器改变了板子能注意到什么

GPIO output provides a state; input adds an outside level; EXTI introduces edge-triggered events; a timer introduces a clock-derived time base. The training sequence therefore moved from a code-controlled LED toward separating level, edge, and timing concepts.

GPIO 输出先给出一个状态，输入再把外部电平带进程序；EXTI 引入边沿触发事件，定时器引入来自时钟的时间基准。这条训练路线因此从“LED 跟着代码变化”，推进到分别理解电平、边沿与计时概念。

The public integration excerpt later places `Encoder_EXTI_Config()`, `TIM3_Config()`, and `TIM4_PWM_Config()` in the same initialization block. Their handlers and callbacks are not public, so the excerpt does not show how or when those entries update program state.

后面的公开综合摘录把 `Encoder_EXTI_Config()`、`TIM3_Config()` 和 `TIM4_PWM_Config()` 放进同一组初始化。它们对应的 handler 与 callback 没有公开，因此摘录不能说明这些入口怎样、又在何时更新程序状态。

## PWM, UART, and ADC Carried Different Kinds of Information / PWM、UART 与 ADC 搬运的是三种信息

The next step was not simply “more peripherals.” PWM represents an output through duty cycle, ADC turns an analog input into a numeric sample, and UART provides a byte stream that can make internal values observable. The public Tianjin files demonstrate the PWM/ADC-side lookup path and OLED output; they do not include a standalone UART listing, so UART remains part of the learning route rather than evidence of a specific integrated branch.

下一步不只是“再多学几个外设”。PWM 用占空比表达输出，ADC 把模拟输入变成采样数值，UART 则提供字节流，让内部数据有机会被观察。天津公开文件展示了 PWM/ADC 一侧的查表路径和 OLED 输出，但没有独立 UART 源码，因此串口只保留为学习路线中的接口与可观察性概念，不写成综合工程里已经展示的分支。

In the visible data path, an ADC-domain target enters `Lookup_PWM_For_Target()`, its result reaches `Set_LED_Brightness()`, and that function writes the TIM4 channel-1 compare value. The progression is from reading numeric data to letting that data select an output compare value.

在可见数据路径里，ADC 域目标值进入 `Lookup_PWM_For_Target()`，结果到达 `Set_LED_Brightness()`，再由该函数写入 TIM4 通道 1 比较值。这里的递进是从读取数值数据，走到让数据参与输出比较值的选择。

## The Main Loop Turned Exercises Into a Demo / 主循环把外设练习接成了 demo

The environment-monitoring excerpt initializes CLED, OLED, LightSensor, TIM3, TIM4 PWM, and encoder EXTI. Inside the loop, `Get_Encoder_Value()` is consumed in the target calculation, a flag is checked before light and DHT11 reads, OLED fields expose current, target, LED-output, temperature, and humidity values, and the lookup result is passed to LED brightness output. That is the point where setup, events, timing, sensing, display, and PWM stop reading like a peripheral checklist.

环境监测摘录初始化了 CLED、OLED、LightSensor、TIM3、TIM4 PWM 与编码器 EXTI。进入主循环后，`Get_Encoder_Value()` 被用于目标值计算，程序在读取光照与 DHT11 前检查一个 flag，OLED 显示当前值、目标值、LED 输出值和温湿度，查表结果再交给 LED 亮度输出。到这里，环境搭建、事件、计时、采样、显示和 PWM 才不再像一张外设清单。

[Environment-monitoring main-loop excerpt](/uploads/projects/tianjin-metro/metro-environment-main-excerpt.c)

The metro setting frames a small STM32F103C8T6 training demo, while PID and ATP/ATO/ATS remain in the accompanying reading layer. Once sensing, target values, display, and output share one loop, the engineering question changes: which part reads or updates each state, and when?

地铁场景框住的是一个小型 STM32F103C8T6 训练 demo，PID 与 ATP/ATO/ATS 仍属于配套阅读层。传感值、目标值、显示与输出开始共享同一个循环后，工程问题也随之改变：每个状态由哪一部分读取或更新，又发生在什么时候？
